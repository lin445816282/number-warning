## 二、核心问题

### 2.1 回测为何不可信

1. **数据窥探偏差（Data Snooping）**：在同一批历史数据上"找规律"再"验证规律"，规律天然被高估。
2. **多重比较（Multiple Testing）**：19 个维度 × 5 个 offset × 多个方案 = 上百次比较，必然产生"看似盈利"的假阳性。
3. **六合彩本质随机**：任何"稳定盈利"的回测结果都值得高度怀疑，需用样本外数据独立验证。

### 2.2 现有前向框架的缺陷

| 项 | 现状 | 问题 |
|---|---|---|
| 触发机制 | 手动「一键匹配」后被动触发 | 不点就不推进，不稳定 |
| 观察池 | `DIM_ASSESS_WATCH` 手动维护 | 可能遗漏/多包含维度 |
| 判定标准 | 100 期 + 超额命中≥5%（简单差值） | 非严格统计检验，无多重比较校正 |
| 样本量 | 100 期阈值 | 只能检测 ~10% 超额；检测 5% 需 ~400 期 |

## 三、目标

建立一个**真实前向验证引擎**，对每个候选维度逐一做样本外论证，用严格统计检验判断维度是否真有预测力，**避免错误下结论**。

## 四、需求定义

### 4.1 验证对象

**全部 19 个维度逐一验证**（不只观察池），每个维度独立前向跟踪。

### 4.2 数据流（真实引擎闭环）

```
开奖数据推送 → 写入主表 → 自动匹配
   ↓
结算昨日选号（命中/未中）
   ↓
基于「截至昨日」数据，固化今日各维度选号
   ↓
（次日重复，永不使用未来数据）
```

**铁律：固化选号时只允许使用 bet_date 之前的数据，严禁数据泄漏（lookahead bias）。**

### 4.3 论证方法（统计检验）

对每个维度，积累 T 期前向样本后：

- **命中率** = hits / T
- **随机基准 p0** = 平均选号数 N / 49（随机选 N 个号的命中概率）
- **超额 alpha** = 命中率 − p0

**二项检验**（单侧）：
- H0：真实命中率 = p0（无预测力）
- H1：真实命中率 > p0（有预测力）
- p 值 = P(X ≥ hits | X ~ Binomial(T, p0))

**多重比较校正**：19 维同时检验，用 Benjamini-Hochberg FDR 控制（或 Bonferroni α/19）。

### 4.4 判定结论（三态）

| 状态 | 条件 | 含义 |
|---|---|---|
| **转正** | p < 0.05（FDR 校正后）且超额为正 | 维度有真实预测力，入核心池 |
| **淘汰** | T ≥ 400 期 且 p ≥ 0.05 | 无预测力，淘汰 |
| **继续观察** | T < 400 期 且未显著 | 数据不足，继续积累 |

> 样本量说明：检测 5% 超额（α=0.05, power=0.8, p0≈0.2）需 ~400 期（约 1 年）。100 期只能检测 ~10% 超额。

### 4.5 字段设计（前向跟踪面板）

每个维度一张前向记录表，字段：

| 字段 | 说明 |
|---|---|
| dim / dim_name | 维度标识 |
| periods | 已结算期数 |
| hits | 命中次数 |
| hit_rate | 前向命中率 |
| avg_n | 平均选号数 |
| rand_base | 随机基准 N/49 |
| alpha | 超额命中 |
| p_value | 二项检验 p 值 |
| verdict | 转正/淘汰/继续观察 |

## 五、分阶段规划

### 阶段 1：引擎骨架（先搭壳）
- [ ] 前向验证专用表 `dim_forward_track`（全维度，非仅观察池）
- [ ] 每日固化逻辑：全维度逐一算今日选号，写入待结算
- [ ] 每日结算逻辑：开奖后结算昨日选号
- [ ] 统计检验函数：二项检验 + FDR 校正

### 阶段 2：自动化触发（真实引擎跑起来）
- [ ] 数据接收后自动匹配 + 自动结算 + 自动固化（去手动依赖）
- [ ] 或 cron 定时任务（每日开奖后固定时间触发）

### 阶段 3：论证面板（可观测）
- [ ] 前向验证面板 API + 前端页面：展示每维度前向命中率/超额/p值/结论
- [ ] 回测 vs 前向对比视图（识别过拟合：回测好但前向差的维度）

### 阶段 4：结论闭环（数据积累后）
- [ ] 达标维度自动转正入核心池（带人工确认）
- [ ] 淘汰维度自动标记
- [ ] 定期复盘报告

## 六、待确认项（需小林拍板）

1. **验证范围**：全部 19 维？还是只回测正期望的 8 个（watch + core）维度？全维度最严谨但样本分散。
2. **触发方式**：数据推送自动触发 vs cron 定时任务 vs 保持手动？
3. **统计阈值**：FDR 校正（推荐）还是 Bonferroni？显著性 α=0.05？
4. **样本量目标**：400 期（检测 5% 超额）还是 100 期（检测 10% 超额）起步？
5. **转正方式**：自动转正还是人工确认后再转正？
