# 统计自欺修复报告：多重比较假阳性清理

**日期**：2026-09-11
**Commit**：本轮（FDR honesty fix）

## 一、发现的问题

自主寻优引擎 `_scan_schemes` 扫了 5385 个方案后，出现严重的方法论自欺：

| 指标 | 数值 |
|---|---|
| FDR（Benjamini-Hochberg）校正后显著 | **0 个** |
| 被转成 `forwarding` 的「弱信号(未校正 p<0.1)」 | **103 个** |
| 其中不含春夏秋冬（已证伪的噪声维度） | 66 个 |
| 弱信号 alpha 均值 | 0.042（命中率仅比随机高 4.2%） |

## 二、根因

`_scan_schemes` 的入选逻辑是：

```python
elif sig and alpha > 0 and avg_n < 20:
    status = "forwarding"  # FDR 显著 → 转前向
elif p < 0.1 and alpha > 0 and avg_n < 20:
    status = "forwarding"  # ❌ 弱信号(未校正 p<0.1) → 也转前向
```

**问题**：既然已经做了 FDR 校正，正确做法是「只看 FDR 显著」。但第二条分支用「未校正 p<0.1」兜底，等于**架空了 FDR 校正的意义**——在 5385 个方案的多重比较下，「未校正 p<0.1」纯碰运气就会冒出几百个假阳性（期望假阳性 ≈ tested × 0.1）。

这直接违背了之前多轮得出的核心结论：
- **信号源唯一**（共识泛化 + 正交扫描两路独立验证）：只有「春夏秋冬憋高位」是真信号，其他维度（生肖/头数/五行/波色/尾数/大小单双）本身零独立信号，只是共识交叉验证的噪声过滤器。

## 三、修复

### 1. 代码修复（`main.py` `_scan_schemes`）

删除「弱信号(未校正 p<0.1)转 forwarding」路径，改为：

```python
elif p < 0.1 and alpha > 0 and avg_n < 20:
    # 未校正 p<0.1 但 FDR 校正后不显著：多重比较下的假阳性，不转前向（诚实原则）
    status = "backtested"
    conclusion = f"未校正p={p}<0.1但FDR校正后不显著，多重比较假阳性，淘汰"
```

### 2. 数据迁移

103 个弱信号 `forwarding` → `backtested`，conclusion 标记「多重比较FDR不显著，已降级淘汰」。

迁移后 status 分布：
- backtested: 5381
- forwarding: **4**（全部是 `season_type + zodiac_color_type` 真信号）

### 3. 前端共识卡片空仓可见化

共识强信号卡片原 `v-if="consensus.consensus2.length"`（无号时整卡隐藏），改为 `v-if="consensus.health"`（加载后常显），无号时显示「今日信号未触发，空仓不下注」。

## 四、验证结论

- ✅ 迁移后 `forwarding` 仅剩 4 个，全部是「春夏秋冬+红肖蓝肖绿肖」真信号维度，与「信号源唯一」结论完全对齐。
- ✅ 前端「今日可下单号码」不再被 103 个噪声方案污染。
- ✅ 自动寻优引擎回到诚实状态：扫 5385 个 → FDR 校正后 0 显著 → 正确结论「数据挖掘无 FDR 显著信号」。

## 五、方法论启示（沉淀）

1. **FDR 校正一旦做了，就必须只看校正后结果**，不能用「未校正 p」兜底，否则校正形同虚设。
2. **多重比较的假阳性是「沉默的杀手」**：103 个弱信号平均 alpha 才 0.042，单独看每个都「有点东西」，合起来全是噪声。
3. **预注册假设 vs 数据挖掘是两回事**：共识信号（season_type+zodiac_color_type 4变体≥2票）是「预注册」的单一假设，p=0.039 有意义；而 `_scan_schemes` 扫 5385 个是「数据挖掘」，必须 FDR 校正，校正后 0 显著是诚实结果。
